# 代码组织

仓库只有一个要发布的程序，按 Go 模块的常规布局维护，不再把源码、模块文件和产品文档堆在根目录或 `prototype/`。

## 目录

| 路径 | 职责 |
|---|---|
| `go.mod`、`go.work` | 模块在仓库根。`go.work` 把主模块和编辑器分叉放进同一个工作区，一条 `go test` 可以一起测。 |
| `cmd/gitclient/` | 桌面客户端，`package main`。`mygo.json`、图标和 `go tool mygo` 都在这里。 |
| `third_party/mygo-editor/` | MyGo v0.5.5 `ui/editor` 的本地分叉，独立模块 `github.com/egoist/mygo/gitclient-editor`。 |
| `docs/` | 需求、计划、验收和测量记录。仓库根只留 `README.md`。 |
| `scripts/` | 原生内存和试用测量。不放业务逻辑。 |

编辑器不能并进主模块。它要 import MyGo 的 `internal` 包，模块路径必须留在 `github.com/egoist/mygo/` 下面。升级时整包替换再打上 `reading-position` 补丁，说明见 `third_party/mygo-editor/README.gitclient.md`。

## 为什么客户端仍是一个包

界面、会话、设置和 Git 调用共享 `app` / `repoTab`，字段在各文件间直接读写。拆成多个包只会把这些字段全部导出，形成互相引用，不会更清楚。这和 Go 自己的 `cmd/go` 一样：一个命令、一个 `main` 包、按文件分职责。

新代码放进已有文件；职责确实独立时再在 `cmd/gitclient/` 加文件，不要另起一套包或测试框架。

| 文件 | 放什么 |
|---|---|
| `main.go` | 窗口、布局、提交表、详情和 diff |
| `model.go`、`graph.go` | 标签状态、提交记录、图谱布局 |
| `repo.go` | 打开仓库、加载、取消和刷新 |
| `git.go`、`process_unix.go`、`process_windows.go` | 只调用系统 Git |
| `auth.go`、`operations.go`、`operation_result.go` | 写操作、确认、认证和失败恢复 |
| `files.go`、`history.go`、`search.go`、`stash.go` | 文件树、历史、搜索、Stash |
| `session.go`、`settings.go` | 会话恢复和用户/仓库设置 |
| `dialog.go`、`terminal.go` | 系统对话框和外部终端 |
| `*_test.go` | 与被测文件放在一起，继续用 `package main` |
| `benchmark_*.go` | 仅 `p0bench` 标签，不进入普通构建 |

## 常用命令

在仓库根。`./...` 不会进入另一个模块，所以编辑器要写进同一条命令：

```sh
go test ./... ./third_party/mygo-editor/...
go test -race ./cmd/gitclient ./third_party/mygo-editor
```

在 `cmd/gitclient/`：

```sh
go run . /path/to/repository
go tool mygo vet .
go tool mygo build -skip-dmg -skip-notarize
```

打包仍在仓库根执行 `./build.command`。
