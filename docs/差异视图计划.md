# 差异视图计划

本文是 `docs/演进计划.md` 的模块 A 的执行计划：diff 视图的四项改动。
总纲里的账本、排期和跨模块规则都在那份文件，这里只写这一模块怎么落地。

起因是对照一个更完整的 diff 审阅工具审阅了一遍我们的 diff 视图。
结论是：**渲染层不用动，缺的是审阅状态。**

## 一、现状

我们的 diff 渲染完全来自 `mygo/ui/editor.DiffView`，两处入口都汇聚到
`app.fileDiffContent`（`cmd/gitclient/compare.go:1594`）：

- 底部详情面板（`compare.go:865`）
- 文件标签页（`file_tabs.go:540`）

`editor.DiffState`（mygo v0.9.0）已经提供的能力，我们一个都没接：

| 字段 | 作用 | 我们用了吗 |
| :--- | :--- | :--- |
| `Wrap` | 长行折行 | ❌ |
| `Bindings` | 给两侧编辑器加按键 | ❌ |
| `LineSelection` | 行号可点选 | ❌ |
| `OnGutterButton` | 行号旁加号按钮（"如评论一行"） | ❌ |
| `Annotations` / `RenderAnnotation` | 行下挂内容（"如审阅评论"） | ❌ |
| `ContextLines` / `ExpandUnchanged` | 上下文行数与全展开 | ❌（用默认 3 行 + 折叠区；见 §二 不抄表） |
| `HunkActions` | 悬停 Revert/Keep | ❌（和 `patch.go` 的块级暂存冲突；见 §二 不抄表） |

`keymap.go:268` 的默认绑定里已经有 `⌘F8` / `⇧⌘F8`（下一个/上一个改动块）
和 `⌘K Z`（折行）。所以有两件事可能今天就能按，只是没人知道。

## 二、抄什么，不抄什么

### 抄（本计划范围）

| 项 | 做到什么程度 | 为什么 |
| :--- | :--- | :--- |
| 折行开关 | 按钮 + 设置项 + 记忆 | 最便宜，纯收益 |
| 改动块键盘导航 | `J` / `K`，只在 diff 里生效 | 审阅时手不用离开键盘 |
| 文件已读 | 已读标记、计数、内容变化自动失效 | 把"看 diff"变成"审 diff"，差距最大 |
| 行级笔记导出 Markdown | 一次性导出到剪贴板，不落盘 | 喂给年轮 / Agent 工作流 |

### 不抄（本计划范围外，不再复议）

| 项 | 为什么不做 |
| :--- | :--- |
| 单滚动面的文件卡片流 + sticky 头部 | 那是 review App 的形态。我们是列表-详情结构的 Git 客户端，改过去要重写文件列表、滚动、聚焦三套模型 |
| PR 拉取 / 评论线程 / approve / request changes | 产品边界。拉进来就要处理 GitHub 认证、线程状态、review 提交，会把客户端拽成另一个产品 |
| 评论持久化 / 回复线程 / 改名后重定位 | 一旦落盘就要跟 rebase、amend、rename 打交道。先验证"我们真的会用"，再谈存储 |
| `HunkActions` 悬停 Revert/Keep | 和 `patch.go` 的块级暂存是两套交互，并存会打架 |
| `ContextLines` / `ExpandUnchanged` 上下文与全展开 | 默认 3 行 + 折叠区已经够读。调大上下文会顶到分页与内存预算（`docs/performance-memory-review-2026-11-02.md` 的口径），全展开走的是没验证过的布局路径。归入未来的「显示选项」菜单一起评估，本计划不动 |
| 内置 AI review（diff 里跑 Agent） | 年轮已经负责 Agent 归属。在 diff 里跑 Agent 是另一个产品，先不碰 |
| 生成文件 / 依赖目录默认折叠 | 有价值但不属于这四项。等文件列表分组改造时一起做 |
| "跳到下一个未读文件" | 需要和主键盘模型对齐，而 `J` / `K` 已被改动块占用。只做已读标记，不做跳转 |

### 一个明确的记账规则

`fileDiffHeader`（`compare.go:1001`）现在有 6 个控件：差异排版、忽略空白、
在 Diff 中查找、底栏全宽、放大阅读、关闭详情。对比视图多一个「从分叉点起」，
图像视图换成「显示方式 + 自适应」。

本计划只往这个头部加一个（折行），加完是 7 个。**导出笔记的按钮放在文件列表
头部**，和第 3 步的 `3/12` 已读计数同一行：那里管的是「这批文件」，diff 头部
管的是「这一段内容」，就近放才不打架。

**触发条件：头部控件到 10 个时，把「忽略空白」「折行」一并收进一个「显示选项」
菜单。** 还剩 3 个名额。到 10 个按这个规则执行，不再单独讨论。

同一条规则也适用于 `fileListHeader`（`compare.go:947`）：它最满的时候是 6 个
（全部暂存、全部取消暂存、返回、列表/树切换、全部展开、全部收起），加上本计划
的已读计数和导出按钮是 8 个。到 10 个同样收进菜单。

## 三、四步落地

每一步都能独立发布、独立回滚。不要四项一起改——它们都要往 `repoTab` 加状态，
前三步还要改同一排按钮，一起上必然返工。

### 第 1 步：折行

**可见结果**：diff 头部多一个「折行」按钮，按下后长行不再横向滚动；重开应用后保持。

**改动**
1. `cmd/gitclient/settings.go`
   - `appPreferences` 加 `Wrap bool \`json:"diff_wrap,omitempty"\``
   - `preferences()` 带上 `Wrap: a.diffWrap`
   - `settingsSection(c, "settings-diff", ...)` 里加一行
     `settingsSwitchRow(c, "settings-diff-wrap", "差异默认折行", "", &a.diffWrap, false, nil)`
2. `cmd/gitclient/main.go`
   - `app` 加 `diffWrap bool`（放在 `diffIgnoreWhitespace` 旁边）
   - 恢复偏好时 `a.diffWrap = p.Wrap`
3. `cmd/gitclient/compare.go`
   - `fileDiffContent` 里 `diff.Wrap = a.diffWrap`（放在 `diff.Layout = ...` 旁边）。
     这一处同时覆盖详情面板和文件标签页。
   - 新增 `diffWrapToggle(c)`，照 `diffIgnoreWhitespaceToggle`（`compare.go:1114`）的形状写，
     文案 `折行`，tooltip `折行显示长行`。
   - 在 `fileDiffHeader` 里，紧跟 `diffIgnoreWhitespaceToggle` 之后调用。
4. `cmd/gitclient/locales/en.json`
   - 补 `折行`、`折行显示长行`。`i18n_ui_audit_test.go` 会拦漏项，但别等它拦。

**不做**：`⌥Z` 快捷键。mygo 的 Binding 只能映射到 `editor.Command`，
`⌥Z` 走不通；而全局监听会和提交信息框、过滤框抢键。`⌘K Z` 是 mygo 自带的，
保留即可，但不写进 tooltip（避免按钮状态和编辑器内部状态两套真值打架）。

**验收**
- 打开一个含超长行的 diff，按「折行」，行在可视宽度内折行。
- 关掉应用重开，状态还在。
- 文件标签页里同样生效。
- `go test ./cmd/gitclient/ -run 'TestI18N|TestDiff'`

### 第 2 步：改动块键盘导航

**可见结果**：在 diff 里按 `J` 跳到下一个改动块，`K` 回到上一个，视图自动居中。

**改动**
1. `cmd/gitclient/compare.go` 新增统一入口：

   ```go
   // prepareDiffState 给每个 diff 装上显示选项和按键，两条渲染路径共用。
   func (a *app) prepareDiffState(d *editor.DiffState) {
       d.Wrap = a.diffWrap
       d.Layout = a.currentDiffLayout()
       d.Bindings = append(editor.DefaultBindings(),
           editor.Binding{Key: ui.KeyJ, Command: editor.NextHunk},
           editor.Binding{Key: ui.KeyK, Command: editor.PreviousHunk},
       )
   }
   ```

2. `fileDiffContent` 里把 `diff.Layout = ...` 换成 `a.prepareDiffState(diff)`。
   第 1 步的 `Wrap` 赋值也并进来。
3. 不加按钮，也不加 tooltip：这批快捷键没有对应控件，挂无可挂。`J` / `K`
   只活在 `DiffState.Bindings` 里，不进 i18n。

**需要先验证的一件事**：mygo 的 `gotoHunk`（`mygo/ui/editor/gitdiff.go:64`）按光标所在行
找下一个改动块。如果点进 diff 不产生光标，`J` 会从文件末尾绕回第一个块。
实测确认；若确实如此，就在 diff 首次获得焦点时把光标放到第 0 行，而不是自己维护
改动块游标（索引会和折叠区展开后的行号漂移）。

**验收**
- 打开一个多改动块的 diff，`J` / `K` 逐块跳，每次滚动到居中。
- 在提交信息框里输入 `j`，不触发跳转。
- `⌘F8` 仍可用。

### 第 3 步：文件已读

**可见结果**：文件行上有一个已读标记按钮；标记后文件名变淡，文件列表标题右侧
显示 `3/12`；文件内容变了自动变回未读。

**改动**
1. 数据模型（`cmd/gitclient/model.go`）

   ```go
   type fileReview struct {
       viewed bool
       stamp  string // 内容指纹，变了就失效
   }

   // repoTab 上新增
   reviewed    map[string]fileReview // key 是文件路径
   reviewCtx   string                // "worktree" 或 "from:to"
   ```

2. 生成指纹：`loadFileDiff`（`compare.go:640`）里，`readFileDiffSource` 成功后，
   对 `source.old` 和 `source.new` 各取 `sha256`，拼成 `stamp`。
   **不要用 `fileChange.status` 判断失效**——`M` 还是 `M`，内容可能已经变了。
3. 失效规则：写入 `t.reviewed[f.path]` 时，指纹不同就把 `viewed` 置回 `false`。
   注意在 `a.post` 的回调里做，文件列表还开着。
4. 上下文切换：`startDiff`（`compare.go:442`）里重置 `t.reviewed = nil`，
   `t.reviewCtx` 设为新的 `worktree` 或 `from:to`。不同对比不共用已读状态。
5. 界面（`compare.go`）
   - `fileHoverActions`（`compare.go:1273`）最左侧加一个勾选按钮，图标 `iconCheck`，
     tooltip 在 `标记为已读` / `标记为未读` 之间切换。
   - 已读文件的文件名改用 `theme.TextMuted`。用布局表达状态，不加"已读"两个字。
   - `fileListHeader` 里，`fileListTitle` 右侧显示 `fmt.Sprintf("%d/%d", viewed, total)`，
     只在已读数大于 0 时出现。**同一屏只出现这一次**，文件行里不再重复。
6. i18n：`标记为已读`、`标记为未读`、`%d/%d 已读` 加进
   `cmd/gitclient/locales/en.json`。

**不做**：持久化。重启后已读清空。理由见"不抄"表：先验证使用量。
**不做**：跳到下一个未读。

**验收**
- 标记 3 个文件已读，头部显示 `3/12`。
- 编辑其中一个文件、刷新，该文件回到未读，计数变 `2/12`。
- 切到另一个对比（比如从 worktree 切到某两个提交），已读全部清空。
- 新增测试 `cmd/gitclient/file_review_test.go`：标记、失效、计数、切换清空。

### 第 4 步：行级笔记导出

**可见结果**：鼠标移到行号上出现加号，点击写一条笔记，笔记显示在该行下面；
头部「复制审阅笔记」把全部笔记连同代码上下文导出成 Markdown 到剪贴板。

**改动**
1. 数据模型：`repoTab.diffNotes []diffNote`，

   ```go
   type diffNote struct {
       Path string
       Side string // "old" | "new"
       Line int    // 行号，从 1 起
       Text string
   }
   ```

2. 接上 mygo 的三个钩子（在 `prepareDiffState` 里设置）：
   - `d.LineSelection = true`
   - `d.OnGutterButton = func(r editor.DiffLineRange) { ... }` 打开输入框
   - `d.Annotations` / `d.RenderAnnotation` 绘制已有笔记
3. 输入框：diff 下方一条覆盖式输入条（不要弹窗），`⌘↩` 保存，`Esc` 取消。
4. 导出：纯函数 `renderNotesMarkdown(d *editor.DiffState, notes []diffNote, path string) string`，
   输出形如：

   ```markdown
   ## cmd/gitclient/compare.go

   ### L1012 (新)

   ```diff
    ...
   -旧行
   +新行
    ...
   ```

   > 笔记正文
   ```

   上下文取笔记行的前后各 3 行。按钮放在 `fileListHeader` 行尾（「全部收起」之后），
   和 `3/12` 同一行，复制到剪贴板，无笔记时禁用；不占 diff 头部（理由见 §二 记账规则）。
5. 生命周期：`diffNotes` 和 `t.reviewCtx` 同生命周期，切对比时和第 3 步的已读在
   同一处清空，不要写成两个 if。只按 `Path` 存的写法不成立——同一个文件在两个
   对比里行号不同，会指到别人身上。

**不做**：持久化、线程、回复、改名后重定位、GitHub 同步。
**不做**：笔记计数角标——会和已读计数在同一屏打架。

**验收**
- 点行号加号、输入、`⌘↩`，笔记显示在该行下方。
- 复制后剪贴板里的 Markdown 含文件路径、行号、三行上下文和笔记正文。
- 切换文件后笔记仍在（内存内），切换对比后清空。
- 新增测试 `cmd/gitclient/diffnotes_test.go`：导出 Markdown 的纯函数快照。

## 四、顺序与时间盒

| 顺序 | 内容 | 时间盒 | 可以独立发布 |
| :--- | :--- | :--- | :--- |
| 1 | 折行 | 0.5 天 | ✅ |
| 2 | 改动块键盘导航 | 0.5 天 | ✅ |
| 3 | 文件已读 | 1 天 | ✅ |
| 4 | 行级笔记导出 | 1.5 天 | ✅ |

先做第 1、2 步，因为它们会验证 `prepareDiffState` 这个统一入口是否站得住。
第 3、4 步都依赖它。

本计划只有这四步。`docs/演进计划.md` 账本里登记的其它模块，一个都不许插进来改变这个顺序。

每步完成后的固定检查：

```sh
go build ./...
go test ./cmd/gitclient/
```

`cmd/gitclient/i18n_ui_audit_test.go` 会检查新增可见文案是否都进了
`locales/en.json`，改文案必须一起改。

## 五、风险

| 风险 | 处理 |
| :--- | :--- |
| `J` / `K` 在输入框里被触发 | 只用 `DiffState.Bindings`，不做全局监听；验收第 2 步第 2 条专门测这个 |
| 折行按钮的 UI 状态与 mygo 内部 `⌘K Z` 状态分叉 | v1 只用 `DiffState.Wrap` 一个真值来源，不做 `⌥Z`；`⌘K Z` 保留但不宣传 |
| 已读指纹要读整份文件，大文件变慢 | 指纹在 `loadFileDiff` 已有的读取结果上算，不新增 IO；`simpleDiff` 降级路径同样适用 |
| 笔记锚点在换行后指错位置 | 明确不做重定位。笔记的生命周期是当前对比（`reviewCtx`），切走就清空 |
| 头部控件过载 | 见第二节的记账规则：到 10 个就收进「显示选项」菜单 |
