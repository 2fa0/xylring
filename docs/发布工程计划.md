# 发布工程计划（模块 J）

本文是 `docs/演进计划.md` 模块 J 的执行计划。本轮只做一件事：**让已安装的 Xylring 自己能发现并装上
新版本**（自动检查、原生更新窗口、手动检查入口、可关掉），顺带把更新日志收成一份。

签名与公证不在本轮：`docs/演进计划.md` 模块 J 的「多平台打包 + 签名增量更新」里，
Apple 证书、notarize、Linux 包都留在后面，这里只动 macOS / Windows 已发布的那两个平台。

**状态（2026-11-13）**：四步都已落地，`go test ./...` 与一次完整的 `./build.command` 都过了；
本机三平台构建已能签出 `update-*.json` 与归档。剩下的三件在最后 §七。

## 一、结论先说：不自己写更新器

MyGo v0.9.0（`go.mod` 里就是这个版本）已经带了完整的更新链路，本项目改造前一行都没用：

| MyGo 现有能力 | 位置 |
| :--- | :--- |
| 签名、清单、增量更新：`mygo build` 把每个平台的包签成 `xylring-<版本>-<target>.tar.gz`，写 `update-<target>.json`，再从最近 3 个已发布版本算 `.delta` | `cmd/mygo/updates.go`（`writeArchive` / `writeDeltas`） |
| 运行时检查与安装：`mygo.Updater.Check` / `Update.Install`，用编进包里的公钥验签，失败就不装 | `updater.go` |
| 现成窗口：Sparkle 那一套（发布说明、Install / Remind Me Later / Skip This Version、下载进度、装完重启），全 Go，无 webview | `plugins/updater`；本项目窗口全是原生 UI，用 `plugins/updater/native` |
| 用户偏好：`updater.json` 里的自动检查、自动下载、上次检查、可用版本 | `plugins/updater/updater.go` |
| 语言：跟着 `App.Locale`，中文在支持列表里 | 同上，§Languages |

所以本轮的活是**接线**，不是实现：把公钥和发布源写进配置、把更新文件塞进 Release、
把插件注册进 app、补菜单和设置页。

### 今天缺的是什么

| 事实 | 位置 |
| :--- | :--- |
| `mygo.json` 没有 `updates`，构建不带公钥、不带清单 | `cmd/gitclient/mygo.json`（全文 8 行） |
| 打包只收集 dmg / setup.exe / zip，`build/` 里的 `*.tar.gz`、`update-*.json`、`*.delta` 被扔掉 | `build.command:75` 之后的收集段 |
| Release 只上传 `release/*`，CI 没有签名密钥 | `.github/workflows/release.yml:49`（`body_path: RELEASE_NOTES.md`） |
| app 没有注册任何插件，菜单里没有更新入口 | `cmd/gitclient/menu.go:9` `installMenu`，`:75` macOS App 菜单 |
| 设置页没有更新分组 | `cmd/gitclient/settings.go:298` `generalSettings`（现有三段：语言与外观 / 差异与文件 / 启动与同步） |
| 版本号两处硬编码：`mygo.json` 与 `cli.go` 的 `defaultVersion` | `cmd/gitclient/mygo.json:4`、`cmd/gitclient/cli.go:16` |

## 二、边界

**做**

- 构建出签名更新文件，Release 带上它们。
- app 注册 `native.Plugin`：启动 10 秒后自动检查，之后每 24 小时一次（插件默认）。
- 菜单「检查更新…」：macOS 在「关于」之后，Windows 在「文件」里设置之前。
- 设置页「更新」分组：自动检查开关、立即检查、当前版本 / 上次检查一行说清。
- 更新日志单一来源：同一份 Markdown 既喂更新窗口的发布说明，又喂 GitHub Release 正文。

**不做（本轮）**

| 不做 | 为什么 |
| :--- | :--- |
| Apple Developer ID 签名 + notarize | 要证书和钱，属于模块 J 后续；本轮包仍是未签名包 |
| 自建源 / S3 源 | GitHub Releases 够用，`updates.github` 一行 |
| 预发布通道（`SetPrereleases`） | 走 GitHub API 才有意义，且要额外的发布纪律；版本稳定后再开 |
| 应用内横幅 / 自绘更新界面 | 插件窗口已经覆盖，再写一套就是两份 UI |
| 设置页「自动下载并安装」开关 | 这个事实由更新窗口的复选框管，两处就是两个真相 |
| Linux 目标 | 本机验证不了，`build.command` 也不产出 Linux 包 |

## 三、四步落地

### 第 1 步：一把签名密钥，构建带出更新文件

**可见结果**：`release/` 里除安装包外，多出 `xylring-0.9.0-darwin-arm64.tar.gz`、同名的 Intel 与
Windows 包、三个 `update-*.json`；第二个版本起还会有 `.delta`。缺密钥时 `build.command` 立刻停下
说清楚缺什么，而不是悄悄产出一个没有更新文件的 Release。

**改动**

1. 密钥只生成一次（丢了就得让所有用户重装）。已经在本机生成过：
   ```sh
   cd cmd/gitclient && go tool mygo keygen
   ```
   产出在 `~/Library/Application Support/mygo/update-keys/`：`mygo-update.pub` 已写进
   `mygo.json`，`mygo-update.key` 需要你放进密码管理器。打包仍然只在本机跑，`build.command`
   自己从这个默认位置读密钥；源码仓库现在虽然公开了，CI 里也没有私钥，所以还是不上传签名。
2. `cmd/gitclient/mygo.json` 加一段（公钥是单行 base64，原样贴）：
   ```json
   "updates": {
     "publicKey": "<mygo-update.pub 的内容>",
     "github": "2fa0/xylring",
     "changelog": "../../CHANGELOG.md"
   }
   ```
   `tagPrefix` 不写就是默认的 `v`，正好对上现有的 `v0.8.2` 标签和 `releases/latest/download/`。
   **源码与发布重新合流**（2026-11-13）：Xylring 开源后，安装包、`update-*.json` 和更新归档
   跟着源码一起发到公开的 `2fa0/xylring`，客户端只读这个仓库的 Releases；私钥不进任何仓库。
   旧的 `2fa0/xylring-release` 只留给已经装着 0.8.3 的用户过渡，0.8.3 的客户端里写的还是它。
3. `build.command`：
   - 构建前取签名密钥：`MYGO_UPDATER_PRIVATE_KEY` 优先，否则读 keygen 的默认位置；两处都没有就
     `fail "找不到更新签名密钥…"`。理由：`mygo build` 缺密钥只会 `warnf`，产出物看起来正常、
     实际不可更新。
   - 构建后从 `build/<target>/` 收集 `*.tar.gz`、`*.delta`、`update-*.json` 进 `release/`，
     和现有 dmg / setup.exe / zip 同一段收集逻辑里做；某个平台一个更新文件都没收集到就直接失败。
4. `.github/workflows/release.yml` 仍不上线：发版要在本机签名，私钥不进 CI。发版是手工上传
   ——`build.command` 结尾会打印要拖上去的文件清单；发布页必须勾 **Set as the latest
   release**，否则 `releases/latest/download/` 还是 404，已安装的客户端查不到新版。
5. `scripts/publish_release.sh`：默认 `TAG` 改成从 `mygo.json` 读版本，发布目标是
   `2fa0/xylring`；不装 `gh` 就在浏览器里传，两条路等价。

**验收**

- 本机跑一次 `./build.command`：`release/` 清单对得上，`build/darwin-arm64/update-darwin-arm64.json`
  里有 `version`、`notes`、`url`、`size`、`signature`。
- 构建输出里不再出现 `Not signing an update`。

### 第 2 步：更新日志只剩一份

**可见结果**：更新窗口里的发布说明和 GitHub Release 正文来自同一个文件的同一段，改一处两处都对。

**改动**

1. `RELEASE_NOTES.md` 改名 `CHANGELOG.md`，头部结构改成 MyGo 认的形状（它按 `## <版本>` 切段，
   子标题必须是 `###`）：
   ```markdown
   ## 0.8.2 - 2026-11-11

   ### 更新内容
   ...
   ### Changes
   ...
   ### 安装包
   ...
   ```
   以后每发布一版在**最上面**加一段 `## 0.9.0 - <日期>`；`go tool mygo build` 找不到当前版本段会
   直接失败（`has no notes`），这是想要的硬拦。
2. `scripts/publish_release.sh` 不再把整份文件当 release 正文，改成先抽出当前版本段落：
   `scripts/release_notes.sh <version>` 一段 `awk`。手工在浏览器发版时，正文就粘它打印的那一段。

**验收**

- `go tool mygo build` 不再报 `has no notes for 0.9.0`。
- Release 草稿正文只有当前版本；更新窗口显示同一段。

### 第 3 步：app 接入更新器

**可见结果**：菜单里出现「检查更新…」；启动 10 秒后自己查一次，发现新版本弹出原生更新窗口，
装完重启进新版本；`go tool mygo dev` 里点检查会说明「这个构建不能自更新」。

**改动**

1. 新文件 `cmd/gitclient/updates.go`：
   - `//go:embed resources/logo.png` 拿窗口图标（插件默认找 `icon.png`，本项目图标叫 `logo.png`）。
   - `mygo.Use(native.New(updater.Options{Icon: logoPNG}))`。
   - 一层薄包装，别的文件只许调这层：`updatesEnabled()`、`checkForUpdates()`、`updatesMenuItem()`、
     `automaticUpdates()` / `setAutomaticUpdates(bool)`、`onUpdatesChange(fn)`、`updatesStatus()`。
     包装内部用包级变量 `updatesReady bool`（注册之后才置真）。理由：`plugins/updater` 的
     `used()` 在插件没注册时直接 `panic`，而 `go test` 和 `--version` 这类 CLI 路径根本不跑
     `main()`。
   - 不需要 `OnInstalled` 钩子：换包后的重启走的是正常退出路径，`main.go` 在 `App.Run` 返回后
     已经 `queueSession` 并等写完，会话不会丢（端到端验收会再验一遍）。
2. `cmd/gitclient/main.go`：在 `RequestSingleInstanceLock` 之后、`mygo.App.Run()` 之前调用注册
   （`mygo.Use` 必须早于 `Run`，放 `WhenReady` 里太晚）。
3. `cmd/gitclient/menu.go`：macOS App 菜单里 `{Role: mygo.RoleAbout}` 之后插 `updatesMenuItem()`
   （`menu.go:75` 那一组），Windows/Linux 的「文件」菜单里放在 `settingsItem` 之前。文案由插件按
   `App.Locale` 给中文，不自造；`OnLocaleChanged` 已经会重装菜单，语言跟随自动生效。
   `updatesMenuItem()` 在插件未注册时返回 nil，菜单照旧。
4. **网络不碰主线程**：本包没有任何 HTTP 调用——检查、下载、验签全在插件自己的 goroutine 和自己的
   连接上。菜单项、设置页按钮都只把请求交出去就返回；设置页读的是插件的内存状态（上次检查时间、
   查到的版本），一帧里不发起请求；`updater.json` 的第一次读盘和「安装位置可写吗」的探测都放在
   启动后的后台 goroutine 里预热（`watchUpdates`），打开设置页那一帧只读内存。断网、超时、被墙
   只让那一次检查静默失败，不弹应用横幅、不挡渲染，下一次启动或下个周期自己重试。
5. **退出途中不再排队重绘**：`OnChange` 回调先看 `a.closed`，应用已经在收尾就直接返回，不往已经
   销毁的窗口上排帧。
6. **能不能更新要如实说**：`updatesUsable()` 只问一次 `mygo.Updater.Enabled()`（会在安装目录里
   试建临时目录）。从 DMG 里直接运行、或装在别的管理员名下时它返回 false，设置页把开关和按钮
   一起置灰，并写清原因，而不是给一个按下去没反应的开关。
5. 键盘/焦点：不新增快捷键，更新窗口是独立窗口，不为它改动主窗口的键位。

**验收**

- 菜单项在两种平台分组正确；切到英文，菜单变 "Check for Updates…"。
- 自动检查在启动 10 秒后发生（`updater.json` 的 `lastCheck` 变化）。
- 开发构建里手动检查：窗口说明不能自更新，不崩、不写坏 `updater.json`。
- 装完重启：版本号变新，上次打开的仓库还在。

### 第 4 步：设置页「更新」

**可见结果**：设置 → 通用页最下面多一个「更新」分组：一个自动检查开关、一行「立即检查」、
以及当前版本与上次检查时间；关掉开关以后不再后台查。

**改动**

1. `cmd/gitclient/settings.go` `generalSettings`（`:298`）末尾加
   `settingsSection(c, "settings-update", "更新", …)`：
   - `settingsSwitchRow`「自动检查更新」↔ `automaticUpdates()` / `setAutomaticUpdates()`，
     值来自插件（`updater.AutomaticChecks()`，默认开）。
   - 检查行：「检查更新」按钮 ↔ `checkUpdates()`，读的是缓存状态，点一下就把请求交给插件。
   - 详情只填必要的一句：有新版本时写「可更新到 0.9.1」，否则写「上次检查：<时间>」；当前版本号
     在这一屏只出现一次。不写「已是最新版本」这类解释，也不复述检查原理
     （`docs/界面文案规范.md`）。
2. `watchUpdates`（`updates.go`）用 `updater.OnChange` 折成一次 `a.post(func(){})` 重绘，让
   「可更新到 …」和「上次检查」当场更新；插件回调本来就在主线程，只读内存状态。
3. 未注册更新器（测试、CLI、将来可能的精简构建）：这一组按禁用渲染，不调用插件包——由第 3 步的
   包装层保证，测试里也不会 `panic`。
4. 新增文案全部 `tr()` 包裹，同一提交补 `cmd/gitclient/locales/en.json`（模块 H 的规矩，先按现有
   测试 `i18n_ui_audit_test.go` 过）。

**验收**

- 开关写进 `updater.json`；关掉后下个周期不再检查（插件 `schedule` 自己处理）。
- 有新版本的构建里，设置页与更新窗口说的是同一个版本号。
- 测试：包装层在未注册时全部走空实现；设置页渲染这一组不碰 `plugins/updater`。

## 六、风险

| 风险 | 影响 | 处置 |
| :--- | :--- | :--- |
| 签名私钥丢失 | 所有已安装用户永远无法再更新，只能重装新包重新引导 | 只在本机 `~/Library/Application Support/mygo/update-keys/`，务必另存进密码管理器；公钥写进 `mygo.json` 前先核对一次 |
| macOS 包未签名未公证 | 自更新写进去的文件不带 quarantine，通常能起来；但首装仍要右键打开，不排除个别系统拦截 | 本轮不改签名；README 现有说明保留，端到端第 2 条专门验一遍「更新后能启动」 |
| 应用装在别的管理员名下（`/Applications` 不可写） | `Updater.Enabled()` 为 false，窗口说明不能自更新 | README 一句「把 Xylring 拖进「应用程序」，不要装在共享目录」；窗口文案由插件给，不自造 |
| 首次发布没有增量包 | 只有下载体积问题 | 接受；第二个版本起自动有 `.delta` |
| 版本号在多处漂移 | 清单里的版本与实际包不一致，更新链断 | 第 1 步的 `build.command` 硬拦密钥、第 2 步的构建硬拦更新日志、第四节的测试拦 `cli.go` |
| GitHub API 限流（60 次/小时/IP） | 检查失败 | 默认 `v` 前缀走 `releases/latest/download/`，不调 API；只有预发布通道才调，本轮不做 |
| 更新时丢仓库会话 | 重启后回到空窗口 | 换包后的重启走正常退出路径，`main.go` 已在 `App.Run` 返回后落盘会话；端到端第 2 条专门验 |
| 测试/dev 构建里插件未注册 | 设置页或菜单 `panic` | 所有调用收在第 3 步的包装层，测试覆盖未注册分支 |
| **上游没有请求超时**（`mygo.Updater` 的 `httpGet`） | 弱网时一次检查可能挂几分钟；后台检查挂住会一直占着 `u.session`，这期间不再自动检查 | 不是泄漏：连接断了就结束，失败后 1 小时重试。用户点「检查更新」会把那个窗口调出来，关掉窗口即取消，之后的检查照常。要根治得给上游补超时，本轮不动 |
| 安装位置不可写 | 插件在窗口里说不能自更新，设置页那一组看起来却可用 | 已按第 3 步第 6 条置灰并说明原因 |

## 七、排期

| 顺序 | 内容 | 时间盒 |
| :--- | :--- | :--- |
| 1 | 密钥 + 构建签出更新文件 + CI 传 secret | 0.5 天 |
| 2 | `CHANGELOG.md` 单一来源 + 两处 release 正文抽取 | 0.25 天 |
| 3 | app 注册更新器 + 菜单入口 | 0.5 天 |
| 4 | 设置页「更新」分组 + 文案 + 三条测试 | 0.25 天 |
| — | 端到端打包与一次真实升级 | 0.5 天 |

合计约 2 天，不含 Apple 签名。四步已落地，剩下的两件事：

1. 把 `~/Library/Application Support/mygo/update-keys/mygo-update.key` 另存进密码管理器
