# 界面文案与层级规范

界面用布局表达结构，文字只表达信息。

用户从布局已经能读到的内容，不要再用文字说一遍。凡是「标题 + 一句解释」的两行结构，
先假设这句解释不存在：如果没人会看不懂，就删掉它。

## 五问自检

改动或新增任何可见文字前，逐条问：

1. 删掉这行字，用户还能不能看懂这里在做什么？能 → 删。
2. 它和同一行、同一张卡片里的其它文字，是不是在说同一件事？是 → 只留一个。
3. 它描述的是「布局」还是「信息」？描述布局 → 删。
4. 它是 git 手册、原理说明或产品介绍吗？是 → 删。
5. 同一个事实（计数、当前值、状态）在同一屏出现几次？多于一次 → 只留一处。

## 这些二级文字是必要的，不要删

- 图标按钮的 tooltip：图标本身没有文字，tooltip 就是它的名字。
- 被截断或省略后放进去的完整信息：全路径、全哈希、完整错误信息。
- 破坏性操作的后果提醒：硬重置、丢弃未跟踪文件、改写已推送历史。
- 只在异常、冲突、降级状态下出现的原因说明。
- 数据本身，不是对数据的解释：作者·时间、分辨率·体积、配置来源 scope、匹配数量。

判断标准是「换一种布局能不能表达同样的事」。能，就不该用文字；不能，就保留。

## 反例对照（已按本规范整改）

| 位置 | 反例 | 问题 | 现在 |
| :--- | :--- | :--- | :--- |
| 搜索建议浮层 | 主标题 + 「按作者筛选提交历史」副标题 + 「作者」徽章 | 三行说一件事，副标题与徽章逐字重复 | 主标题 + 类型徽章；只有作者·时间这类数据保留副标题 |
| 文件列表空状态 | 「没有文件变化」+「这两个版本没有文件差异」 | 标题和描述是同一句的两种写法 | 一句完整的话直接作标题 |
| 获取远程对话框 | 顶部常驻「从所有远程获取最新引用。不会合并或改动工作区。」 | 解释标题已经说完的事 | 删除 |
| 筛选横幅 | 「正在按说明筛选：“x” · 匹配 N 个提交」+ 底栏「N 条提交」 | 同一数字同屏两次 | 横幅只说筛选条件，计数只留底栏 |
| 提交信息卡片 | 标题「完整提交信息」+ 按钮「复制完整信息」 | 按钮重述标题 | 按钮改图标，tooltip 与无障碍名保留 |
| 设置行 | 开关关闭时补一句「应用后将从此范围移除此项设置」 | 开关状态本身已经说明 | 删除；确有需要时进 tooltip |
| 操作对话框 | 软重置 / 推送分支 / 设置身份 的 git 语义说明 | 手册，不是本次操作的额外信息 | 只保留有后果的（硬重置、混合重置、恢复历史文件、删除 Stash、中止操作、继续操作） |
| 设置行 | 每行都挂一个 `全局` / `项目` scope 徽章 | 与所在标签页（Git = 全局、当前项目 = 本地）重复 | 只在生效值来自更高优先级范围时才显示 |
| 当前项目页 | 「本项目自动获取」 | 与所在标签页重复 | 改成「检查频率」，让分组标题「自动获取」负责说明语境 |
| 首页空状态 | 「支持直接拖拽文件夹至窗口」 | 拖拽时本来就有全屏浮层解释，闲置时常驻一句是重复 | 删除；浮层在真正需要时说明 |
| 筛选状态 | 横幅「退出筛选」+ 工具栏「返回」两个入口 | 同一动作两个按钮 | 只留搜索框旁的「返回」，横幅降为状态说明 |

## 新增文案时的落位决策

| 信息类型 | 放在哪里 |
| :--- | :--- |
| 控件是什么、当前值 | 可见文案，一处 |
| 图标按钮的名字 | tooltip |
| 被截断内容的完整版 | tooltip |
| 不可逆操作的后果 | 可见警示，紧贴确认按钮 |
| 这里为什么是空的 | 空状态一句话，不要「标题 + 描述」两行 |
| 统计数字、状态 | 一处，通常是底栏或所在区块的头部 |
| 键盘快捷键 | 键帽，不要写进按钮名或 tooltip 正文 |

## 实现约定

- `emptyHintProps` 优先把一句话写进 `Title`。`Description` 只在确实需要补第二种信息时才用，
  不要用它把标题换个说法再说一遍。
- 一组条目（列表项、建议项、设置行）每项最多「主文案 + 一个类型徽章」，
  禁止「主文案 + 副标题 + 徽章」三段式。
- 一个控件不要同时用可见标题、状态副行、无障碍名重复同一状态。
- 新增可见文案必须用 `tr()` 包裹，并在 `cmd/gitclient/locales/en.json` 补键；
  删除文案时顺手删掉失效的键。`TestTranslationCoverageAndFormats` 会拦住漏加的字面量。

## 改完 UI 的检查清单

```sh
grep -rn "Description:" cmd/gitclient    # 新加的描述是否为第二种信息
grep -rn "subtitle" cmd/gitclient        # 是否又出现三段式条目
go build ./... && go test ./...
```

再用 `ui.NewTester` 或真机逐屏问一遍：有没有两行在说一件事、有没有解释布局的文字。
